# DOCX 修改与格式保护

## 项目身份

每次生成后检查：

- 文件名
- 封面题目与副标题
- 页眉、页脚
- 自动目录
- 正文和附录
- 图题、表题
- DOCX 核心属性

模板中出现其他项目名称时，必须在交付前清除。

## 封面与署名

- 沿用用户指定模板；没有固定模板时，通过标题层级、留白、版心和少量统一色彩改善阅读，不强制居中或指定一种配色。
- 项目名称、报告类型、作者、单位、日期和版本按实际用途选取，标题与署名保持可编辑；不得用一张整页图片替代可编辑封面。
- 指导教师、顾问、审核人等角色不是必填项。仅保留用户要求或已有确认的身份信息，不虚构人员，不因删除某个角色而删除作者、团队或单位。
- 将用户已确认的字段增删和版式选择带入后续版本，不能在重新生成时恢复被删除的字段。清除目标字段时检查关联文本框、页眉页脚和属性；保护其他信息。
- 封面独立成页，分节与分页方式保持可维护，不靠大量空行定位；检查标题换行、文字间距、视觉重心以及后续修订页的位置。

## 自动目录

以下要求用于启用目录的 DOCX；用户模板或配置关闭目录时跳过目录检查。其他格式采用其自身目录机制。

目录必须能够自动更新。程序检查以下内部标记，这些内容不写入成稿：

- `instrText` 中存在 `TOC`
- 有 `fldCharType=begin/separate/end`
- `settings.xml` 中 `updateFields=true`

批量润色时跳过包含 `fldChar` 或 `instrText` 的段落。直接改写目录文字可能删除自动更新所需的信息，使目录变成普通文字。

保留目录字段、书签、链接和层级。`updateFields=true` 只表示请求更新，不能证明缓存页码正确；用排版工具刷新后，将目录页码与渲染正文核对。前置页不显示正文页码，第一章从 1 起算。无法刷新时明确目录页码未验证。

## 表格保护

仅润色正文时：

1. 记录上一版表格的数量和文字内容。
2. 遍历 `document.paragraphs`，不要遍历表格单元格。
3. 修改后再次比较表格数量和文字内容。
4. 发现差异时停止交付并定位原因。

表格结构调整属于单独任务，不能混在正文润色中。

本轮已授权修订表格内容时，先列出允许变化的表格、单元格或新增行，再逐项比较。新增修订行不能改写历史版本、日期和描述；既有列宽、行高、合并单元格与样式也须检查。正文润色使用变更后的表格作为本步骤的保护基准。全表哈希只能判断文字是否完全相同，不能解释差异，也不能证明表格版式一致。

## 正文缩进

“所有段落首行缩进”按正式报告规则解释为正文段落：

- 正文首行缩进 2 个中文字符
- 标题、目录、图表题注、项目符号、代码块和表格不缩进
- 使用 `firstLineChars=200`，并设置兼容的 `firstLine` 值

以上为中文默认排版。英文或其他模板使用用户指定的段落样式，不调用专用中文双字符缩进检查。增加修订记录等已授权表格变化时，将新增表格与原有表格分开比较，不能将预期新增误判为数据损坏。

修改后抽查正文页和表格页。

## 图片附录与互引

附录照片应覆盖整体、内部、关键组件、交互区和维护结构。每张图包含：

- 附图编号
- 简洁题注
- 可见部件或观察点

正文至少有一处引用每张附图。检查正文中的“图、附图、表”引用是否存在对应题注。

## 局部修改

用户指出具体页码、图片或表述时：

1. 先在文档内部结构、正文或渲染页面中定位。
2. 判断用户说的是界面功能、文档功能还是软件按钮。
3. 修改精确对象及必要上下文。
4. 重新检查相邻页、目录、页数和交叉引用。

同步定位同一术语在标题、正文、表头、题注、图内文字和附录中的用法，避免只改正文而留下矛盾。扩展修改限于本轮要求和必要上下文；例如删除资料叙述不等于删除合法的“测试记录”或历史修订说明。保留先前已确认的删除项、封面和配图要求，图像替换后检查未改动图片是否仍完整。

不要把“Word 目录没有更新按钮”误解为项目界面缺少更新按钮。

## 版本交付

- 不覆盖用户认可的版本。
- 文件名能区分本轮目的。
- DOCX 中理解报告所必需的图片应内嵌，检查文档、页眉页脚等部件的图片关系及媒体文件；普通参考文献超链接可以保留。正文独立性仍需人工通读，图片关系检查不能覆盖外部数据域、嵌入对象或技术语义。
- 具备工具时完整渲染并逐页检查；结构检查、字数统计和生成成功不能替代版面验证。按配置如实标明跳过或未完成项。
- 最终报告说明修改范围和检查结果，不暴露内部工作文件。
