# 创新点提炼与后续落地

## 创新点判断

创新点必须能回答四个问题：

1. 原有问题是什么。
2. 本项目采用了什么不同做法。
3. 该做法带来什么可观察变化。
4. 当前验证到什么范围。

创新不等于器件清单。常规器件组合只有在接口、结构、算法、控制或交互上产生新关系时，才适合写为系统集成创新。

## 创新类型

| 类型 | 可写对象 | 常见误区 |
|---|---|---|
| 结构 | 分区、装配、维护、防护、制造 | 把外观变化写成结构创新 |
| 感知 | 采样、融合、标定、质量判断 | 只有传感器型号 |
| 算法 | 数据处理、识别、规划、评价 | 只有模型文件 |
| 控制 | 状态机、互锁、滞回、容错 | 把普通开关写成智能控制 |
| 系统 | 多模块接口、数据一致性、异常链 | 只罗列模块 |
| 交互 | 状态解释、操作反馈、可用性 | 只修改颜色或图片 |
| 工程 | 测试、配置、复现、维护方法 | 把一般规范写成重大创新 |

## 创新点表述模板

> 针对【具体问题】，项目在【对象】中采用【具体做法】。该做法改变了【接口、流程或结果】。目前已通过【实际验证】确认【有限结论】；【尚未验证事项】留待下一阶段完成。

避免“国内领先、行业首创、显著提升、填补空白”等无法核验的表述。

## 当前完成阶段

按当前资料选择状态：

- 方案：有原理和设计。
- 模块原型：单模块已实现。
- 集成原型：主要模块已连接。
- 场景验证：在目标场景有测试记录。
- 工程样机：完成可靠性、安全和可维护性验证。
- 产品准备：成本、制造、合规和服务方案明确。

报告只写达到的阶段，不跨级推断。

## 后续落地路径

根据项目类型选择必要步骤：

1. 补齐原型功能和实测数据。
2. 完成安全、可靠性和长期运行测试。
3. 优化结构、BOM、功耗和制造工艺。
4. 组织目标用户任务测试。
5. 确认并保存版本、配置、接线、标定和交付包。
6. 评估知识产权、合规、隐私和维护责任。
7. 选择项目展示、竞赛、科研验证或小规模试用场景。

每一步写负责人、前置条件、输出和完成标准。没有市场调研时，不估算销量或商业回报。
