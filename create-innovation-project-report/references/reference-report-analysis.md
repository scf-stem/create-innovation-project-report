# 参考报告结构与篇幅分析

## 分析目标

参考报告用于确定结构深度、章节比例和信息密度。只借鉴组织方式，不复制其项目事实、指标、图片或无关格式说明。

## 统计维度

按一级和二级标题记录：

- 正文字符数
- 正文段落数
- 表格数及表格行数
- 图片与题注数
- 代码、公式和列表数量
- 主要信息类型

若能够渲染 PDF，再记录章节起止页和页数。只有 DOCX 时使用字符数、段落数、表格和图片进行比较，不伪造页数。

## 内容深度判断

| 深度 | 特征 | 处理建议 |
|---|---|---|
| 低 | 只有概念介绍或成果结论 | 补职责、接口、实际步骤和边界 |
| 中 | 有方案和实现说明 | 补选择原因、关键参数和验证过程 |
| 高 | 有输入输出、参数、问题和测试 | 保持信息密度，删除重复解释 |

技术章节的高信息密度通常来自具体接口、数据流、配置、时序、代码片段、测试条件和异常处理，不来自更长的背景说明。

## 对比方法

1. 建立参考报告与当前报告的章节对应表。
2. 比较同类章节字符数、表格数和图片数。
3. 标记缺少“实现细节、验证、问题处理”的章节。
4. 检查当前项目是否有资料支持扩写。
5. 有资料才扩写；没有资料则写边界或测试计划。

## 从深度差异形成具体改进项

用内部对照表将“章节—缺少的解释—本项目可用材料—拟补充内容—验证方式”对应起来。不要将参考报告的篇数、页数或图数当作验收配额。

- 需求章节补具体使用动作、约束和可判断的目标。
- 方案章节补备选方案、选择理由和舍弃条件。
- 实现章节补连接对象、接口、参数含义、操作顺序及异常处理。
- 实施章节补问题现象、排查方法、改动及复测结果；无法确认时间时按阶段写，不推测日期。
- 验证章节补装置或环境、样本、步骤、判定标准、观察结果和局限；没有结果时交付明确的测试计划。
- 创新章节将具体变化与已展示的实现或验证对应，避免仅增加形容词。

完成后逐项检查新增内容能否解释项目如何实施、为何这样设计以及结果支持到什么程度。仅增加背景套话、同义重复或来源描述不能解决内容不够具体的问题。

## 防止机械模仿

- 参考报告有章节，不代表当前项目必须保留。
- 参考报告篇幅长，不代表当前报告需要等量扩写。
- 参考报告中的精确指标不得迁移。
- 不复制“资料依据、编写说明、参考文献说明”等编写过程章节，除非提交模板明确要求。
