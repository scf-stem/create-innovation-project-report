# 创新项目综合报告结构建议

保留“需求—设计—实现—验证—成果—复盘”的主要叙述顺序，再按项目类型选择模块。不要机械复制固定章节。

以下核心章节用于默认 `project_only` 正式报告，遵循 [四条成稿规则](content-policy.md)。缺少实际测试结果的对象用功能分析或处理设计说明，不把设计改写成测试通过。未完成事项、范围外目标和未来计划只在用户明确要求的 `progress` 任务中按范围增加。

## 核心章节

### 1. 摘要

用一段话交代项目对象、主要架构、核心功能、实际工作和工程成果。关键词选技术对象和应用方向。

### 2. 项目概述

说明项目定位、使用场景、系统组成、项目范围和交付形态。先用一段话建立全貌，再用模块表概括职责。

### 3. 背景与需求分析

写具体问题、参与对象、环境条件、功能需求和非功能约束，说明需求如何对应架构和模块职责。

### 4. 项目目标与功能体系

说明核心功能、工程对象与输入输出关系。实现、分析和设计分别命名，设计目标不能写成已达到结果。

### 5. 技术路线与系统架构

说明备选方案、选择理由、实施顺序、系统分层、数据流、控制流和异常流。配架构图或流程图。

### 6. 核心模块实现

根据项目复杂度安排章节。每章说明职责、方案、接口、关键配置、实际工作、测试和限制条件。

### 7. 系统集成与功能分析

按模型、接口、子系统和整机协同关系组织，有实际记录时说明测试条件与结果。仿真、协议示例和设计关系具有明确对象，不增加待测清单。

### 8. 典型问题与处理

选择有工程价值的问题，按“现象—定位—原因—处理—结果—经验”展开。

### 9. 创新点与项目特色

创新点与具体实现、对比对象和验证程度对应。没有足够支撑时写“项目特色”。

### 10. 工程成果与应用价值

按实际存在的源码、模型、图纸、实物、数据和方法列成果，解释其在系统中的作用与适用场景。

### 11. 关键工程设计与实践总结

写关键技术处理、设计取舍、配置关系和工程方法，说明实现过程中的具体做法。

### 12. 综合总结

概括项目完成范围、主要结果和当前完成阶段，不夸大为成熟产品。

## 按项目类型选择内容

简要报告可合并概述与需求、实现与结果、特色与总结；详细报告仅在资料充分时扩展。无源码的研究、设计或服务项目按实验、设计和业务流程组织，不补写不存在的代码接口或硬件装配。方案资料说明设计原理，测量和运行资料说明实际结果；计划仅用于明确的进度任务。

### 实验研究与数据分析

- 研究问题、实验或采样条件
- 样本来源、数据处理、分析方法与可复现步骤
- 实际观测、误差、不确定性和适用范围
- 结果讨论与方法分析

### 业务流程与服务项目

- 服务对象、任务、触点和流程
- 角色职责、交付物和执行条件
- 实际试点、反馈、流程指标和问题处理
- 应用条件、操作流程和维护责任

### 农业物联网与环境控制

- 机械分区、水电隔离和风道
- 温湿度、光照、土壤或气体采集
- 标定、数据质量与单位换算
- 执行器、互锁、滞回和安全关闭
- 上位机、交互和长期数据记录

### 机电与机器人

- 机械结构和运动机构
- 主控、驱动、电源和通信
- 感知、定位、规划和运动控制
- 安全状态、急停和整机联调

### AI、视觉与算法

- 数据来源、标注和划分
- 预处理、模型与训练配置
- 推理接口、部署和资源消耗
- 指标定义、对照方案和误差分析

### 纯软件与信息系统

- 用户角色、业务流程和数据模型
- 前后端架构、接口和权限
- 异常处理、日志、性能和安全
- 可用性测试和部署维护

### 产品设计与交互装置

- 用户任务、信息架构和交互流程
- 结构、材料、加工和装配
- 界面状态、反馈与误操作保护
- 用户体验测试和维护路径

## 可选章节

只有提交模板或项目实际需要时添加：

- 团队分工；计划仅用于进度模式
- 阶段成果；未完成进度仅用于进度模式
- 参考文献
- 知识产权与合规
- 成本与 BOM
- 实物照片附录
- 原始数据或测试记录附录

内部资料清单、编写口径、扫描过程和自检记录不进入成稿。

## 常用表格

- 场景与需求表
- 需求—设计—实现—验证追踪表
- 方案比较与选型表
- 系统模块职责与接口表
- 环境、版本和配置表
- 硬件接口与信号表
- 实验数据与测试结果表
- 典型问题与处理表
- 创新点与验证状态表
- 成果清单与系统作用表
