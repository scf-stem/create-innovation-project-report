# 图片与 DOCX 质量规范

## 选图原则

图片应证明项目做了什么，或帮助读者理解系统如何工作。每张图至少满足一个目的：

- 展示真实结构、实物或装配关系
- 展示代码、界面、运行状态或测试结果
- 解释架构、流程、数据流或控制逻辑
- 对比问题处理前后的关键差异

删除装饰性、重复性、与正文无关或无法辨认的图片。

## 图片来源顺序

1. 项目文件夹中的原始图片和截图
2. 从 DOCX、PPTX、PDF 中提取的原始媒体
3. 对现有截图进行裁切、去除幻灯片边框和无关文字
4. 官方或可信页面的通用硬件照片
5. 新生成的结构、原理、架构和流程示意图

通用硬件图片只能说明器件外观或类别，不能证明项目实际使用了该型号。网络图片应保存来源信息供内部确认，但是否在成稿中列出处取决于提交要求。

## 生成图与重制图

保持全篇风格一致：

- 使用统一的线条粗细、配色、字体感和视角
- 图内只保留短标签、箭头、端口名和必要状态
- 不在图片内部放置与图题重复的标题
- 不把段落、操作步骤或 PPT 说明文字塞进图中
- 不伪造实物、测试结果、软件界面或测量数据

生成图适合架构、流程、原理和概念关系，不适合作为“已完成测试”的证据。

机械爆炸图按 [exploded-view-and-appendix.md](exploded-view-and-appendix.md) 执行。优先使用 CAD 原生爆炸视图；使用图像生成时必须提供真实项目参考图和零件清单。

## 标注与题注

- 图内标注控制在词组级，如“相机输入”“识别节点”“停车指令”。
- 图题控制在一行内，如“图 7-2 控制系统硬件连接关系”。
- 正文在图前或图后解释观察重点，不重复朗读题注。
- 同一章节使用“图 章节号-序号”编号。
- 正文使用“见图 7-2”或“见附图 A-1”引用，引用编号必须存在对应题注。
- 用户要求“不要标题”时，先确认指图内标题还是图题；批注目标明确时只改该图。

## 实物照片附录

照片较多时，从以下视角选择代表图：

- 整体外观
- 开门或拆盖后的内部布局
- 关键执行器、传感器或控制板
- 界面和操作区域
- 后部、底部或维护结构

附录每张照片写“附图 A-1”式编号和可见部件说明。正文相关章节至少引用一次。相似角度、信息重复或无法辨认的照片不纳入。

正文和编号稳定后使用 `scripts/appendix_images.py` 终装，禁止在润色或目录更新过程中反复删除、复制附录图片。

## 版面检查

- 图片保持原始比例，不拉伸。
- 单图宽度不超过版心；细节截图可使用全宽。
- 多图组合要有一致高度、间距和子图标识。
- 图与题注保持同页，题注后留出适当段间距。
- 低分辨率图片不要放大到文字无法辨认。
- 以“源像素 ÷ 文档中实际英寸尺寸”计算有效 PPI。用户要求 300 dpi 时，按有效 PPI 检查，不只修改图片 DPI 元数据。
- 裁切时保留任务栏、坐标、图例或状态栏中真正有证据价值的部分。

## 渲染检查清单

- 封面信息完整且居中
- 目录页码与标题层级正常
- 标题不落在页尾
- 图题、表题与对象没有跨页
- 表格没有超出版心或截断
- 图片没有压扁、模糊、遮挡正文
- 中文字体没有替换为乱码
- 页眉、页脚和页码连续
- 章节编号、图号、表号连续
- 最后一页没有异常空白或残留说明

每次大改后完整渲染。局部修改后至少复查修改页、前后相邻页、目录和最后一页。
